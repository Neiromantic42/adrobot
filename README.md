# Adrobot: обёртка над Keitaro

Тестовое задание. Веб-приложение на FastAPI + SQLAlchemy, которое работает с трекером Keitaro через Admin API.

1. **Создатель кампаний.** Название, гео-код страны и ID оффера создают кампанию с двумя потоками: первый ловит указанную страну и редиректит на Google, второй отправляет трафик на оффер. Домен, группа и источник проставляются автоматически.
2. **Редактор кампании.** Загружает потоки существующей кампании, позволяет добавлять и удалять офферы, закреплять веса, отменять и публиковать изменения. Веса пересчитываются автоматически.

## Стек

Python 3.12, FastAPI, SQLAlchemy 2, Alembic, SQLite, httpx, pytest. Фронт: статические HTML-страницы с обычным JavaScript (без сборки).

## Быстрый старт

```bash
git clone https://github.com/Neiromantic42/adrobot.git
cd adrobot
python3 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt

cp .env.example .env               # затем впишите адрес Keitaro и API-ключ
python -m alembic upgrade head     # создаёт базу adrobot.db и таблицы
uvicorn app.main:app --reload
```

Приложение откроется на http://127.0.0.1:8000

- `/` создание кампании
- `/editor.html` редактор кампании
- `/docs` Swagger со всеми эндпоинтами

### Настройки (`.env`)

| Переменная | Описание |
|---|---|
| `KEITARO_URL` | адрес Keitaro без `/admin` и без слеша на конце |
| `KEITARO_API_KEY` | ключ Admin API (в админке: профиль, API ключи) |
| `DATABASE_URL` | по умолчанию `sqlite:///./adrobot.db` |
| `DEFAULT_DOMAIN_ID`, `DEFAULT_GROUP_ID`, `DEFAULT_TRAFFIC_SOURCE_ID` | необязательно: домен, группа и источник для новых кампаний (по умолчанию 1813, 10332, 836) |

```bash
python -m alembic upgrade head                              # применить

```

Alembic запускается через `python -m alembic`, чтобы использовалось окружение проекта.

Тесты не обращаются к Keitaro (используются заглушки), но для импорта настроек нужен файл `.env` (подойдёт копия `.env.example`).

## Как пользоваться редактором

1. Откройте `/editor.html`, введите ID кампании в Keitaro, нажмите **Fetch streams**.
2. Потоки без офферов показываются просто как поток. В потоках с офферами видны названия и веса.
3. **Add**: введите ID или название оффера, выберите из подсказок. **Remove**: оффер становится серым с весом 0%. **Pin**: фиксирует вес. **Bring back**: возвращает удалённый оффер из архива.
4. Поток с неопубликованными изменениями окрашен в жёлтый. **Push to Keitaro** публикует изменения, **Cancel** отменяет их.

## Как это устроено

В Keitaro нет понятия «черновик», поэтому локальная база хранит то, чего у трекера нет: неопубликованные изменения, закреплённые веса и архив удалённых офферов.

**Состояния оффера в потоке**

| Состояние | Значение |
|---|---|
| `active` | оффер есть в Keitaro |
| `pending_add` | добавлен локально, ещё не опубликован |
| `pending_remove` | удалён локально, ещё не опубликован (вес 0) |
| `removed` | архив: оффер удалён и опубликован |

Поток считается «жёлтым» (`dirty`), если в нём есть `pending_add`, `pending_remove` или `active`-оффер, чей вес отличается от опубликованного (`published_weight`). Флаг не хранится, а вычисляется.

**Пересчёт весов** (`app/services/weights.py`): закреплённые веса не меняются, остаток до 100 делится поровну между остальными, лишние единицы раздаются по +1 первым (три оффера дают 34/33/33). Если сумма закреплённых весов больше 100, возвращается ошибка.

**Fetch** (`app/services/sync.py`): оффер есть в Keitaro, значит `active` с весом из Keitaro. Оффер пропал из Keitaro (удалён руками), значит `removed`. Неопубликованные `pending_*` не затираются, поэтому Fetch блокируется (409), пока в потоке есть неопубликованные изменения. Потоки, удалённые в Keitaro, удаляются и локально.

**Push** (`app/services/push.py`): в Keitaro отправляется полный список офферов потока (`PUT /streams/{id}`) при условии, что сумма весов равна 100. Локальное состояние меняется только после успешного ответа.

## API

| Метод | Путь | Что делает |
|---|---|---|
| POST | `/api/campaigns` | создать кампанию (`name`, `geo`, `offer_id`) |
| POST | `/api/campaigns/{keitaro_id}/fetch` | загрузить кампанию из Keitaro |
| GET | `/api/campaigns/{keitaro_id}` | локальное состояние кампании |
| GET | `/api/offers/search?q=` | поиск оффера по ID или названию |
| POST | `/api/streams/{id}/offers` | добавить оффер (`offer_id`) |
| DELETE | `/api/stream-offers/{id}` | удалить оффер из потока |
| POST | `/api/stream-offers/{id}/bring-back` | вернуть оффер из архива |
| POST | `/api/stream-offers/{id}/pin` | закрепить или открепить вес (`pinned`) |
| POST | `/api/streams/{id}/cancel` | отменить неопубликованные изменения |
| POST | `/api/streams/{id}/push` | опубликовать изменения в Keitaro |

`{id}` в путях потоков и офферов это локальный id из ответа API, а не id Keitaro.

## Ограничения

- Нет авторизации: приложение рассчитано на одного пользователя.
- Для поиска оффера скачивается весь справочник офферов Keitaro (без постраничной загрузки).
- Редактор работает с потоками, в которых есть офферы; остальные потоки показываются как есть.
- Откат при сбое создания кампании (удаление уже созданной кампании) покрыт кодом, но вручную не проверялся.
